BVTech MSP Command Center v32.0 — POLISH EDITION
====================================================

WHAT THIS IS
------------
A unified dashboard for running an MSP business out of one window:
prospect scraping, multi-channel content publishing, HubSpot CRM
sync + email tracking, security audits, M365 inbox, DialPad calling,
and a local automation engine that runs scheduled tasks even when
the UI is closed.

Everything runs locally on your Windows machine. No SaaS, no
subscriptions beyond the APIs you already pay for.


QUICK START
-----------
1. Run INSTALL.bat   (first time only — installs Python deps)
2. Run Start-BVTech.bat
3. Open http://localhost:5678  (the installer opens it for you)
4. Settings tab → paste your API keys
5. The "What's New" popup auto-shows on first launch — read it,
   close it, you're good.

WHAT'S NEW IN v32 (POLISH EDITION)
-----------------------------------
- Channel-specific content rewrites
  When you publish to "All 4 Channels" (BVTech + JordanPolasek +
  LinkedIn + GBP), the master article is now rewritten by Claude
  into 4 distinct voices instead of posted verbatim everywhere.
  BVTech gets corporate authority, JP gets first-person personal,
  LinkedIn gets a hook-driven 1200-char post, GBP gets a 300-char
  local-search blurb. Stops Google's de-dup filter from penalizing
  you for duplicate content.

- Staggered scheduler
  Four new scheduled tasks (disabled by default) publish ONE
  channel per day instead of all four at once:
    Monday    -> BVTech.org
    Wednesday -> JordanPolasek.com
    Friday    -> LinkedIn
    Saturday  -> Google Business Profile
  Pulls from a local post queue. Enable them on the Automation tab
  once you've added items to the queue from Super Posting.

- Post queue
  Pre-generate post ideas, drop them in the queue from the Super
  Posting tab. The staggered scheduler tasks fire one channel at a
  time per item until all 4 are done.

- Retroactive backlinks (standalone CLI)
  retroactive_backlinks.py walks your existing local blog folder
  and injects "Related Posts" blocks into old posts using the
  posts_index.json data. Idempotent (re-running does nothing),
  has --dry-run by default, makes backups before writing.

  Example:
    python retroactive_backlinks.py --site bvtech \
        --site-root "C:\BVTech2\Website\bvtech.org"
  Then re-run with --commit to actually write.

- Draft & Track
  New button on the HS Track tab. Builds a mailto: URL with your
  HubSpot BCC address pre-injected, opens your default mail client
  (Gmail, Outlook, whatever), and pre-logs the contact to HubSpot.
  Send manually, BCC catches it, HubSpot logs it. Best of all
  worlds, no SMTP relay landmines.

- Polish pass
  - Tab bar reorganized into core / outreach / ops / infra /
    advanced groupings
  - Stripped 30+ "v20 NEW" / "v25 NEW" / "v18 KEY FIXES" graffiti
    from every tab
  - Deleted orphan Guardz tab (unreachable)
  - Hid WordPress tab from the bar (legacy fallback still in code)
  - Removed 7 runtime junk files that had been shipping in zips
    since v27 (prospects.csv, scrape_cache.json, sent_log.csv, etc.)
  - All changelog history moved to the "What's New" modal

See CHANGELOG_v32.md for the complete writeup.


RUNNING WITHOUT THE EXE
-----------------------
You don't need to compile to .exe. Just:
  1. python -m pip install flask requests
  2. python bvtech_app.py
The Start-BVTech.bat script does this for you.


WINDOWS TASK SCHEDULER INTEGRATION
-----------------------------------
v31 added the ability to install BVTech tasks as Windows scheduled
tasks. v32 extends this with the 4 staggered publishing tasks.

To install a task to Windows Task Scheduler:
  1. Open the Automation tab
  2. Find the task you want
  3. Click the "⊕ Win" button
  4. Confirm

The task is registered with schtasks.exe under the prefix
"BVTech_". View them in taskschd.msc. The Windows Task Scheduler
will fire the task on its schedule even when BVTech itself is
closed — it shells out to:

  pythonw.exe bvtech_app.py --run-task <taskname>

Which runs the task and exits without starting the Flask server.


HUBSPOT EMAIL TRACKING SETUP (5 minutes)
-----------------------------------------
1. HubSpot → Settings → Integrations → Private Apps → Create
2. Add scopes:
     crm.objects.contacts.read
     crm.objects.contacts.write
     crm.objects.emails.write
3. Copy the Private App access token
4. BVTech → Settings → HubSpot CRM → Private App Token → paste
5. (Optional but recommended) HubSpot → Settings → Objects →
   Activities → Email tab → copy "Forward to HubSpot" address
6. BVTech → HS Track tab → BCC field → paste → Save
7. Click "Verify Connection" — should show your portal ID

Now every email you send and BCC to that address auto-logs to the
matching contact's timeline in HubSpot. For one-offs you can also
use the manual log form on the HS Track tab.


GOOGLE BUSINESS PROFILE OAUTH SETUP
------------------------------------
GBP API access is gated by Google. You have to apply for access
before localPosts.create will work. Without approval, you'll get
HTTP 403 on every post attempt.

1. console.cloud.google.com → create or pick a project
2. Enable: My Business Account Management API,
           My Business Business Information API,
           Google My Business API
3. Fill out the access request form:
     https://support.google.com/business/contact/api_default
   Wait 1-2 business days for approval email.
4. Create OAuth 2.0 credentials (Web application type)
5. Add redirect URI: http://localhost:5678/api/gbp/oauth/callback
6. Paste Client ID + Secret into Settings → Google Business Profile
7. Click "Connect Google Business" → consent → done


CLOUDFLARE PAGES DEPLOY SETUP
------------------------------
v29 rewrote the deployer to walk your entire local site folder
and upload via the Direct Upload protocol (same as wrangler pages
deploy). v30+ uses this for both BVTech.org and JordanPolasek.com.

Required config (Settings → Cloudflare):
  cf_api_token            Your Cloudflare API token
  cf_account_id           Your Cloudflare account ID
  cf_project_name         The Pages project name (e.g. bvtech-org)
  bvtech_site_root        Local path to bvtech.org folder
                          (e.g. C:\BVTech2\Website\bvtech.org)
  jp_site_root            Local path to jordanpolasek.com folder

Then on the Super Posting tab, click "Test Deploy" first to do a
dry-run that walks the folder, hashes everything, and asks
Cloudflare what it would upload — without actually deploying.


UPGRADING FROM v31 OR EARLIER
------------------------------
1. Unzip v32 to a NEW folder (e.g. C:\BVTech_v32\)
2. Run INSTALL.bat
3. The installer auto-migrates these files from your previous
   version folder if found:
     bvtech_config.json     (your API keys + settings)
     posts_index.json       (cross-linking history)
     local_events.db        (v31+ event log)
4. Done. Your old folder is untouched — keep it as a backup.

If migration didn't happen automatically, manually copy those
three files from your old version folder.
