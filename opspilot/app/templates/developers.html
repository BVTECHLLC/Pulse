Developer Hub

Pulse is a platform — drive it from anything. Authenticate with an API key, subscribe to events, or push events in. The full machine-readable spec lives at /api/openapi.json (import it into Postman, Zapier, Make, or a code generator).

1 · Authentication — API keys

Create a key in the dashboard under Integrations → API Keys. Send it on every request as the X-API-Key header. A key acts with the role and client scope of the user who created it.

curl https://portal.bvtech.org/api/clients \
  -H "X-API-Key: pulse_xxxxxxxxxxxxxxxxxxxxxxxx"

Session cookies and Authorization: Bearer <token> also work for interactive use; API keys are the right choice for tools and automation.

2 · Outbound webhooks — react to Pulse

Subscribe any URL under Integrations → Outbound Webhooks. We POST a JSON body for each event; verify authenticity with the HMAC signature header.

POST your-url
X-OpsPilot-Event: ticket.created
X-OpsPilot-Signature: sha256=<hmac>
Content-Type: application/json

{ "event": "ticket.created", "data": { ... }, "ts": "..." }

Verify in Python:

import hmac, hashlib
def verify(secret, body_bytes, header):
    expected = "sha256=" + hmac.new(secret.encode(), body_bytes,
                                    hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header)

3 · Inbound ingest — push into Pulse

Create an endpoint under Integrations → Inbound Ingest; we mint a URL any tool can POST JSON to. We create a ticket or alert for the bound client.

curl -X POST https://portal.bvtech.org/api/ingest/<token> \
  -H "Content-Type: application/json" \
  -d '{"subject":"Disk full on web-01","body":"95% used","priority":"high"}'

Recognized fields: subject/title, body/message, severity (alerts), priority (tickets). The token is the credential — no other auth needed.
